# kiln — Paper Layer（笺）

同一窑的釉，一半烧成器，一半印在纸上。

工作台层管信息密集的工作表面。这一层管同一个产品里**不是工作台**的那些表面 —— 它们过去没人管，于是每个产品的登录页都从别处抄一套视觉，用户从登录页走到第一个数据表时，风格在门口就断了。

## 这一层管什么

覆盖：登录 / 注册 / 找回密码、空状态、404 / 500 / 无权限、报表封面与导出首页、发布说明与更新日志、系统邮件（通知、邀请、重置密码）、产品门面首屏。

不覆盖：任何工作台表面。

判据只有一句：**这个表面上有没有"要反复做的工作"？** 有 → 工作台层，读 `components.md` 和 `layouts-and-pages.md`。没有 → 这一层。一个表面同时有两者（例如登录页上嵌了一张待办表格）说明它被塞了不属于它的东西，先拆，再套层。

## 继承什么，反转什么

**继承（固定层，改了就不是 kiln 了）：**

- 同一套釉色 palette。纸面不新增任何裸色值，`tokens/paper.css` 里每个颜色都从 `colors.css` 派生。
- 单锚点：一屏只有一个高饱和信号。
- 反装饰：无渐变泼墨、无 3D、无霓虹、无立体浮雕按钮、无库存插画。
- token 是唯一真相源，业务代码零裸色值。
- 字号**下限**（`--text-tiny`）。读不了的字，在哪一层都是读不了。

**反转（工作台的规则在这一层失效）：**

| 维度 | 工作台 | 纸面 |
| --- | --- | --- |
| 密度 | 紧凑，信息优先 | 留白优先，见下 |
| 分层手段 | 暖黑柔和阴影，白卡浮在画布上 | 颗粒、细线、压痕 —— **纸不浮在纸上面** |
| 字号天花板 | `--text-data` | `--text-display` |
| 视觉主体 | 一屏多个数据区并置 | 一个能被清楚表现的主体 |
| 正文 | `--text-body` | `--text-paper-body` |
| 空白的含义 | 待填的浪费 | 结构本身 |

## 留白是硬约束

纸面页面的**墨占比**（与纸底色有可见差异的像素比例）必须落在 `scripts/verify-paper.mjs` 断言的区间内，实测校准，不靠眼估。

为什么把它写成会失败的检查，而不是"多留点白"这种建议：留白一旦滑出区间，页面既不是纸也不是工作台，而是掉进中间态 —— 信息稀疏的工作台。那是所有失败版本里最难看的一种，且它每次都是一点一点滑过去的，没有任何一次改动看起来像是错的。

留白必须是**连续的大块**，不是均匀摊开的行距。一张纸上的空白应该能让人一眼看出主体在哪儿。

## 一个主体

一张纸上只有一个视觉事件：一句话、一个标记、一个表单、一张封面标题。

其余元素只能是它的注脚 —— 更小、更淡、贴边。如果两个元素在争夺"先看哪个"，这张纸就还没设计完。这条在工作台层的对应物是三层层级；到了纸面，层级从三层收到两层：**主体，和其它**。

## 材质是印刷的，不是屏幕的

- **`--shadow-card` 及一切柔光阴影在这一层禁用。** 纸不会浮在纸上面。工作台用阴影把白卡从画布里托起来，那是屏幕的语言；纸面用颗粒和线。
- 允许的质感只有三种：`--paper-grain`（颗粒 / 网点）、`--paper-rule`（印刷细线）、`--paper-edge`（压痕 / 折线）。
- 颗粒必须极轻，是"看不见但感觉得到"的量。能一眼看出网点图案，就已经过了。
- 表面层次靠 `--paper` 与 `--paper-deep` 的换面，不靠投影。

## 锚点在纸上的形态

工作台里锚点是一个按钮填充 —— 小面积、高饱和、承担唯一关键动作。

纸面上它可以换形态：一个色块、一条粗规则线、一枚印章式标记、一个被涂红的字。**数量不变，永远只有一个。** 换形态是可以的，换成两个不行。

登录页的提交按钮就是那一个。如果页面已经用一个红色块做了视觉锚，提交按钮就必须降到 ink 或描边 —— 两个红一起出现，这一层和工作台层同时失去信号。

## 字体

默认仍然是 Noto Sans SC，和工作台同一套。

纸面层**可以**引入 Noto Serif SC，条件是三条同时成立：同族同源（同一 CDN、同一字重命名）、只用于 `--text-display` 和 `--text-title`、正文与控件仍走 sans。这是 `platform-mapping.md` 里"字体家族属于可变层"的一次合法使用，不是新开一个字体系统。

不许引入第三个 webfont。打字机体、圆体、任何 display face 都不行 —— 一个衬线已经足够把纸面和工作台区分开。

## 页面蓝图

**登录 / 注册**：单栏居中，纸面占满视口。主体是表单，标题用 `--text-title`，产品名与副标题贴在表单上方。表单宽度收紧到内容需要的宽度，不铺满。提交按钮是那唯一的锚点。辅助链接（忘记密码、注册）用 `--paper-muted`，贴表单下沿。

**空状态**：一句说明为什么没有数据，一个说明接下来能做什么的动作。不要插画。空状态出现在工作台**内部**时按工作台层处理，这里说的是整页级的空。

**404 / 500 / 无权限**：数字或状态词用 `--text-display`，一句人话解释，一个回到安全处的动作。不要幽默文案。

**报表封面 / 导出首页**：标题、时间范围、生成方、一条 `--paper-rule` 分隔。封面的作用是让人知道这份东西是什么、什么时候的、谁出的 —— 除此之外的一切都是装饰。

**发布说明**：版本号是主体，条目是注脚。按变更类型分组，每组之间用留白而不是卡片分隔。

**系统邮件**：单栏，宽度按邮件客户端收紧。不能依赖 webfont（多数客户端不加载），字体栈退回系统栈是**预期行为**，不是缺陷；因此邮件里的层级只能靠字号、字重和留白，不能靠字体区分。

## QA

- 墨占比落在 `verify-paper.mjs` 的区间内。
- 计算样式里没有任何 `box-shadow`（除 `none` 外）。这一层禁用柔光阴影。
- 高饱和像素只聚成一个色相簇 —— 锚点唯一。
- 字号不低于 `--text-tiny`。
- 字体栈含 Noto Sans SC；若引入衬线，它只出现在 display / title 元素上。
- 在 1440 宽和 390 宽各看一次：纸面页面在窄视口下最容易把"连续的大块留白"摊成均匀的行距。

## 反模式

- 在纸面上使用 `--shadow-card` 或任何柔光阴影，把纸做成浮起的白卡。
- 用满屏渐变、模糊光斑、几何装饰填补留白 —— 留白是结构，不是待填的空。
- 一屏两个高饱和锚点，例如一个红色标题块加一个红色提交按钮。
- 库存插画、3D 图示、拟物图标。空状态尤其容易犯。
- 把工作台的紧凑密度直接搬到登录页：13px 正文、36px 控件、贴边排布 —— 结果是一张"缩水的工作台"，而不是一张纸。
- 幽默或俏皮的错误文案。这一层的语气和工作台一致：直陈事实，给出下一步。
- 为了填满视口而把表单拉宽到整页。控件宽度是对内容的声明，这条在两层通用。
- 引入第二个 display 字体来"更有设计感"。
- 在纸面页面里嵌真实的工作数据表格。那说明这个表面被塞了不属于它的东西。
